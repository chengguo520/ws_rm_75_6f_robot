Stability update
----------------
Date: 2026-05-26

Symptom:
Gazebo showed visible shaking after startup and MoveIt planning/execution could
fail with an invalid-bounds start state.

Likely cause:
The first Gazebo migration used the official 6F collision/inertia model with no
joint dynamics and a very stiff, weakly damped position PID:
p=1000, d=0.1. In Gazebo this can create startup oscillation. If the current
joint state jitters outside URDF limits even slightly, MoveIt rejects the start
state as invalid bounds.

Fix applied:
1. Added damping/friction to joint1..joint7 in rm_75_6f_gazebo.urdf.xacro:
   damping=5.0, friction=1.0
2. Changed Gazebo ros_control PID gains to a more conservative setup:
   p=250, i=0, d=20
3. Changed Gazebo initial spawn pose from all-zero to the SRDF forward pose:
   joint1=0
   joint2=0.8395
   joint3=0
   joint4=1.4442
   joint5=0
   joint6=0.8513
   joint7=0

Validation:
check_urdf still succeeds.
catkin build rm_75_6f_description rm_75_gazebo rm_75_moveit_config --summarize
succeeds.


Ground-plane update
-------------------
Date: 2026-05-26

Symptom:
The base looked like it was sinking into the Gazebo ground plane.

Cause:
The Gazebo-only bottom_link is attached below base_link. With base_link spawned
at z=0, the bottom plate intersects Gazebo's built-in ground_plane.

Fix applied:
The fixed dummy_joint now raises base_link by 0.03 m:
dummy -> base_link origin xyz="0 0 0.03"

This makes the bottom plate sit on the ground instead of penetrating it.

Validation:
check_urdf succeeds.
catkin build rm_75_6f_description rm_75_gazebo rm_75_moveit_config --summarize
succeeds.
