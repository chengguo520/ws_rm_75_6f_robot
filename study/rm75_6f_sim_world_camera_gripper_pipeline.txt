RM75-6F 仿真叠加流程学习笔记：世界模型 + RGB-D 相机 + 视觉识别 + MoveIt 规划避障 + 夹爪模型
================================================================================

工作区：

  /home/ros/ws_rm_75_6f_robot

核心目标：

  1. 在 Gazebo 世界里摆放桌子和蓝色方块。
  2. 在 URDF/xacro 里加入一个固定 RGB-D 相机，放在世界/root 坐标附近俯视桌面。
  3. 通过相机彩色图 + 深度图识别蓝色方块，计算方块在 base_link 下的位置。
  4. 把桌子、方块加入 MoveIt planning scene，规划机械臂末端运动到方块上方，并避开桌子/方块。
  5. 在 link7 末端加入两指夹爪固定模型，并定义 gripper_tcp_link 作为真正的夹取中心。


一、整体框架
--------------------------------------------------------------------------------

这套实验里有三个“世界”，要分清楚：

  1. Gazebo 世界
     负责真实仿真显示、物理、碰撞、相机传感器数据。
     文件是：
       /home/ros/ws_rm_75_6f_robot/src/rm_75_robot/rm_75_gazebo/worlds/rm75_table_cube.world

  2. Robot URDF/xacro
     负责机械臂本体、夹爪、相机这些“机器人模型树”里的 link/joint/sensor。
     文件是：
       /home/ros/ws_rm_75_6f_robot/src/rm_75_robot/rm_75_6f_description/urdf/rm_75_6f_gazebo.urdf.xacro
       /home/ros/ws_rm_75_6f_robot/src/rm_75_robot/rm_75_6f_description/urdf/two_finger_gripper_fixed.xacro

  3. MoveIt planning scene
     负责规划时的障碍物。Gazebo 里有桌子，不等于 MoveIt 自动知道桌子。
     需要脚本主动把桌子/方块作为 collision object 加进去。
     当前由脚本负责：
       /home/ros/ws_rm_75_6f_robot/src/rm_75_robot/rm_75_demo/scripts/sim_02_vision_approach.py

一句话理解：

  Gazebo 负责“仿真里有什么”。
  RViz 负责“可视化 MoveIt 知道什么”。
  MoveIt 只会避开 planning scene 里的 collision object。


二、启动命令
--------------------------------------------------------------------------------

先进入工作区：

  cd /home/ros/ws_rm_75_6f_robot
  source devel/setup.bash

注意：

  你的 .bashrc 默认可能 source 旧工作区：
    /home/ros/ws_rm_75_robot/devel/setup.bash

  所以做 RM75-6F 实验前一定要 source 新工作区：
    source /home/ros/ws_rm_75_6f_robot/devel/setup.bash


推荐启动：桌子 + 方块 + 夹爪，暂时不开相机

  roslaunch rm_75_gazebo arm_75_bringup_moveit.launch \
    world_name:=$(rospack find rm_75_gazebo)/worlds/rm75_table_cube.world \
    use_two_finger_gripper:=true \
    rviz_software_rendering:=true


推荐启动：桌子 + 方块 + RGB-D 相机 + 夹爪

  roslaunch rm_75_gazebo arm_75_bringup_moveit.launch \
    world_name:=$(rospack find rm_75_gazebo)/worlds/rm75_table_cube.world \
    use_rgbd_camera:=true \
    use_two_finger_gripper:=true \
    rviz_software_rendering:=true


参数含义：

  world_name:=...
    指定 Gazebo 加载哪个 world 文件。这里加载带桌子和方块的 rm75_table_cube.world。

  use_rgbd_camera:=true
    让 rm_75_6f_gazebo.urdf.xacro 展开时加入 RGB-D 相机 link、joint、Gazebo sensor。

  use_two_finger_gripper:=true
    让 rm_75_6f_gazebo.urdf.xacro 展开时加入两指夹爪模型。

  rviz_software_rendering:=true
    让 RViz 单独使用软件渲染，避免 WSLg + D3D12 + RTX 3050 下 RViz 不显示机械臂模型。
    Gazebo 仍然可以走 RTX 3050。


三、GPU/RViz 显示策略
--------------------------------------------------------------------------------

你的 WSL2 里 RTX 3050 是可用的，Gazebo 可以使用：

  GL_RENDERER = D3D12 (NVIDIA GeForce RTX 3050 Laptop GPU)

但是 RViz 走 D3D12/RTX 时出现过“机械臂模型不显示”，所以我们采用分离策略：

  Gazebo：
    使用 GPU 渲染。

  RViz：
    单独软件渲染，保证模型显示。

这个逻辑已经写进 launch：

  /home/ros/ws_rm_75_6f_robot/src/rm_75_robot/rm_75_gazebo/launch/arm_75_bringup_moveit.launch

主 launch 里：

  <env name="LIBGL_ALWAYS_SOFTWARE" value="0" />

RViz launch 里：

  <env if="$(arg software_rendering)" name="LIBGL_ALWAYS_SOFTWARE" value="1" />

所以日常启动时只要带：

  rviz_software_rendering:=true


四、世界模型：桌子和方块
--------------------------------------------------------------------------------

文件：

  /home/ros/ws_rm_75_6f_robot/src/rm_75_robot/rm_75_gazebo/worlds/rm75_table_cube.world

里面定义了两个静态模型：

  vision_table
    pose: 0.45 0.00 0.28 0 0 0
    size: 0.60 0.80 0.04
    color: brown

  vision_cube
    pose: 0.45 0.10 0.325 0 0 0
    size: 0.05 0.05 0.05
    color: blue

为什么方块 z 是 0.325？

  桌子中心 z = 0.28
  桌子厚度 = 0.04
  桌面高度 = 0.28 + 0.04 / 2 = 0.30
  方块边长 = 0.05
  方块中心高度 = 0.30 + 0.05 / 2 = 0.325

也就是说，方块正好放在桌面上。

六、视觉识别方块的原理
--------------------------------------------------------------------------------

脚本：

  /home/ros/ws_rm_75_6f_robot/src/rm_75_robot/rm_75_demo/scripts/sim_02_vision_approach.py
  /home/ros/ws_rm_75_6f_robot/src/rm_75_robot/rm_75_demo/scripts/sim_04_vision_pick.py

默认识别：

  蓝色方块

命令：

  rosrun rm_75_demo sim_02_vision_approach.py --color blue

如果想执行规划轨迹：

  rosrun rm_75_demo sim_02_vision_approach.py --color blue --execute

如果想执行完整“视觉识别 -> 预抓取 -> 夹取 -> 抬升”链路：

  rosrun rm_75_demo sim_04_vision_pick.py --color blue --execute \
    --velocity 0.2 --acceleration 0.2

视觉识别流程：

  1. 订阅彩色图：
       /camera/color/image_raw

  2. 订阅深度图：
       /camera/depth/image_raw

  3. 订阅相机内参：
       /camera/color/camera_info

  4. 使用 cv_bridge 把 ROS Image 转成 OpenCV 图像。

  5. BGR 转 HSV。

  6. 按颜色阈值分割蓝色区域：
       blue HSV roughly:
         H: 95 - 130
         S: 70 - 255
         V: 60 - 255

  7. 找最大轮廓，计算图像中心像素：
       u, v

  8. 在深度图中读取该像素附近的深度：
       depth

  9. 用相机内参把像素转成相机坐标系下的 3D 点：
       x = (u - cx) * depth / fx
       y = (v - cy) * depth / fy
       z = depth

  10. 用 TF 把点从相机坐标变换到 base_link：
        rgbd_camera_optical_frame -> base_link

  11. 输出检测到的方块位置：
        Detected object base xyz: x, y, z


七、TF 和坐标系链路
--------------------------------------------------------------------------------

重要坐标系：

  dummy
    URDF 根部 dummy link。

  base_link
    机械臂底座坐标系。

  link7
    机械臂第七轴末端 link，也就是法兰/夹爪安装位置。

  gripper_tcp_link
    夹爪 TCP 坐标系。加了夹爪以后，MoveIt 脚本应优先用它作为 end effector link。
    它位于两个手指之间，代表夹爪中心，而不是机械臂法兰中心。

  rgbd_camera_link
    相机本体 link。

  rgbd_camera_optical_frame
    相机光学坐标系，深度点云和彩色图通常使用这个坐标系。

相机点转换流程：

  像素 + 深度
    -> rgbd_camera_optical_frame 下的 PointStamped
    -> tf2 transform
    -> base_link 下的 PointStamped

检查 TF：

  rosrun tf view_frames

或：

  rosrun tf tf_echo base_link rgbd_camera_optical_frame


八、MoveIt planning scene 与避障
--------------------------------------------------------------------------------

关键知识点：

  Gazebo 里的桌子和方块，不会自动变成 MoveIt 的障碍物。

所以脚本会主动加 collision object：

  scene.add_box("vision_table", table_pose, size=(0.60, 0.80, 0.04))
  scene.add_box("vision_cube", cube_pose, size=(0.05, 0.05, 0.05))

对应脚本函数：

  setup_demo_scene(scene, spawn_gazebo)
  add_detected_object(scene, base_point)

对象名：

  vision_table
  vision_cube

planning scene 相关话题：

  /planning_scene
  /planning_scene_world
  /move_group/monitored_planning_scene
  /collision_object
  /attached_collision_object

脚本使用：

  PlanningSceneInterface()

MoveIt 会根据 planning scene 里的 collision object 做碰撞检测，所以只有加入 planning scene 的桌子/方块才会被规划器避开。

重要理解：

  Gazebo 负责“仿真显示与物理碰撞”。
  MoveIt 负责“路径规划与碰撞检测”。
  两边不是同一个数据库。


九、MoveIt 规划到方块上方
--------------------------------------------------------------------------------

脚本里规划组：

  GROUP_NAME = "arm"

末端 link：

  EEF_LINK = "gripper_tcp_link"

参考坐标系：

  BASE_FRAME = "base_link"

现在默认采用侧向夹取接近，而不是继续把 link7 移到方块上方。

侧向接近目标：

  x = 方块 x - side_offset
  y = 方块 y
  z = 方块 z

默认 side_offset：

  0.04 m

含义：

  让 gripper_tcp_link 位于方块前方 4 cm，夹爪夹持部分靠近工件。
  TCP 的 X 轴朝向方块，夹爪开合方向沿桌面横向。
  夹爪主平面平行桌面，两个夹持内侧面垂直桌面。

如果需要让工件进入两指中间，使用 sim_04_vision_pick.py 或 sim_03_gripper_pick.py 的 grasp 阶段：

  pre_grasp:
    x = 方块 x - 0.04
    z = 方块 z + 0.02

  grasp:
    x = 方块 x
    z = 方块 z + 0.02

此时 gripper_tcp_link 对齐方块中心，工件位于两指夹持部分中间。
这里的 0.02m z 偏移是为了给夹爪和桌面留出碰撞余量。

如果还想保持旧的“到方块上方”实验，可使用：

  --approach-mode top

top 模式目标：

  x = 方块 x
  y = 方块 y
  z = 方块 z + approach_z

默认 approach_z：

  0.12 m

也就是说，当前夹爪实验默认不是把法兰移到方块上方，而是把夹爪中心移动到方块前方的预抓取点。

运行规划但不执行：

  rosrun rm_75_demo sim_02_vision_approach.py --color blue

运行规划并执行：

  rosrun rm_75_demo sim_02_vision_approach.py --color blue --execute

降低速度：

  rosrun rm_75_demo sim_02_vision_approach.py --color blue --execute \
    --velocity 0.2 --acceleration 0.2

只看检测，不想每次重新加场景：

  rosrun rm_75_demo sim_02_vision_approach.py --color blue --no-setup-scene

如果 world 文件没有桌子/方块，也可以让脚本动态 spawn 到 Gazebo：

  rosrun rm_75_demo sim_02_vision_approach.py --color blue --spawn-gazebo


十、完整视觉抓取脚本 sim_04
--------------------------------------------------------------------------------

sim_04_vision_pick.py 是 sim_02 与 sim_03 的融合版：

  1. 读取 RGB-D 相机图像。
  2. 识别蓝色方块。
  3. 计算方块在 base_link 下的位置。
  4. 清理 sim_02/sim_03 可能留下的 planning scene 物体。
  5. 加入 table/object collision object。
  6. MoveJ 到 pre_grasp。
  7. 如果带 --execute，继续 MoveL 到 grasp。
  8. 模拟 attach object。
  9. MoveL lift。

只检测并规划 pre_grasp：

  rosrun rm_75_demo sim_04_vision_pick.py --color blue

执行完整视觉抓取：

  rosrun rm_75_demo sim_04_vision_pick.py --color blue --execute \
    --velocity 0.2 --acceleration 0.2

常用参数：

  --pre-grasp-offset 0.04
    预抓取点在方块前方 4cm。

  --grasp-offset 0.0
    grasp 阶段 TCP 对齐方块中心。

  --grasp-z-offset 0.02
    TCP 比检测到的方块中心高 2cm，给夹爪和桌面留碰撞余量。

  --lift-distance 0.12
    抓取后抬升 12cm。

  --keep-scene
    脚本结束后保留 MoveIt planning scene 中的桌子/方块，便于 RViz 观察。

夹爪 mesh 已复制到：

  /home/ros/ws_rm_75_6f_robot/src/rm_75_robot/rm_75_6f_description/meshes/gripper_base_link.STL
  /home/ros/ws_rm_75_6f_robot/src/rm_75_robot/rm_75_6f_description/meshes/gripper_Link1.STL

颜色：

  绿色

夹爪挂载位置：

  parent="link7"
  xyz="-0.010 0 0.045"
  rpy="0 -1.5708 0"

说明：

  这个 -0.010 m 是为了补偿官方夹爪 STL 模型自身原点偏心。
  调整后夹爪底部中心基本对齐机械臂末端中心线。

夹爪 TCP：

  link name:
    gripper_tcp_link

  parent:
    gripper_base_link

  xyz:
    0.096 0 -0.010

  含义：
    X 轴：从夹爪根部指向两个手指中间的前方。
    Y 轴：两个手指开合方向。
    Z 轴：夹爪厚度方向。

  当前 TCP 更靠近指尖夹持区域。换算到 link7 后，TCP 大约在法兰前方 0.141 m：

    link7 -> gripper_tcp_link ≈ (0, 0, 0.141)

  MoveIt 规划时应该优先控制 gripper_tcp_link，而不是 link7。

启动夹爪：

  use_two_finger_gripper:=true

当前夹爪状态：

  只是固定模型。
  可以显示，可以参与碰撞。
  不能开合。

后续如果要做真实抓取，需要继续补：

  1. 夹爪活动关节。
  2. transmission。
  3. ros_control gripper controller。
  4. MoveIt SRDF 里加入 gripper group。
  5. 抓取动作：open -> approach -> close -> lift。

十四、常见问题
--------------------------------------------------------------------------------

问题 1：RViz 里看不到桌子/方块。

原因：

  Gazebo world 里的模型不会自动进入 RViz/MoveIt planning scene。
  RViz 的 MotionPlanning 主要显示 MoveIt planning scene。

处理：

  运行 sim_02_vision_approach.py 时，它会把桌子/方块加入 planning scene。
  当前 sim_02 脚本默认以 gripper_tcp_link 作为末端，规划夹爪中心到方块前方 4 cm 的侧向接近点。
  当前 sim_03 脚本会继续从 pre_grasp 直线进入 grasp，使工件位于两指中间。


问题 2：Gazebo 有桌子，MoveIt 规划却会穿桌子。

原因：

  桌子只在 Gazebo，不在 MoveIt planning scene。

处理：

  用 PlanningSceneInterface.add_box() 加入桌子。


问题 3：脚本识别不到蓝色方块。

检查：

  rostopic list | grep camera
  rqt_image_view /camera/color/image_raw

可能原因：

  没有 use_rgbd_camera:=true。
  Gazebo 里没有蓝色方块。
  相机视野没对准方块。
  HSV 阈值不合适。


问题 4：有检测结果，但是 MoveIt 规划失败。

检查：

  方块位置是否太靠近机械臂不可达区域。
  side_offset 是否太小，导致夹爪太靠近方块或桌子。
  如果使用 --approach-mode top，再检查 approach_z 是否太小。
  当前机械臂姿态是否奇异。
  planning scene 是否把目标点包进障碍物里。

可尝试：

  --approach-z 0.16
  --velocity 0.2 --acceleration 0.2


问题 5：Gazebo 用 GPU 后 RViz 不显示机械臂。

处理：

  启动时加：

    rviz_software_rendering:=true

这会让 Gazebo 走 GPU，RViz 单独走软件渲染。


十五、推荐实验顺序

第 1 步：只开桌子和方块

  roslaunch rm_75_gazebo arm_75_bringup_moveit.launch \
    world_name:=$(rospack find rm_75_gazebo)/worlds/rm75_table_cube.world \
    use_two_finger_gripper:=true \
    rviz_software_rendering:=true

  Gazebo 和 RViz 里末端出现绿色夹爪。

  roslaunch rm_75_gazebo arm_75_bringup_moveit.launch \
    world_name:=$(rospack find rm_75_gazebo)/worlds/rm75_table_cube.world \
    use_rgbd_camera:=true \
    use_two_finger_gripper:=true \
    rviz_software_rendering:=true

检查：

  rostopic list | grep camera
  rqt_image_view /camera/color/image_raw

  rosrun rm_75_demo sim_02_vision_approach.py --color blue

  rosrun rm_75_demo sim_02_vision_approach.py --color blue --execute \
    --velocity 0.2 --acceleration 0.2


第 6 步：完整视觉抓取链路

  rosrun rm_75_demo sim_04_vision_pick.py --color blue

确认 pre_grasp 规划成功后，再执行：

  rosrun rm_75_demo sim_04_vision_pick.py --color blue --execute \
    --velocity 0.2 --acceleration 0.2
