================================

目标：

不看教程，自己完成实物连接、启动、检查、关闭。

必须记住的启动顺序：

终端 1：

cd /home/ros/ws_rm_75_6f_robot
source devel/setup.bash

终端 2：

cd /home/ros/ws_rm_75_6f_robot

检查：

rosnode list

/rm_75/follow_joint_trajectory/result
/rm_75/follow_joint_trajectory/status

核心链路：

RViz / MoveIt
  -> /rm_75/follow_joint_trajectory

  -> rm_driver
  -> socket 192.168.1.18:8080
  -> 真实机械臂
  -> /joint_states
  -> robot_state_publisher
  -> /tf
  -> RViz

阶段 2：掌握 ROS 排错基本功
=========================

目标：

遇到“Plan 成功但机械臂不动”，能定位是哪一层断了。

必须熟悉的命令：

rosnode list
rostopic list
rostopic info /话题名
rostopic echo /话题名
rosparam get /参数名
rosservice list
rosservice call /服务名
rqt_graph

典型检查顺序：

1. 机械臂网络是否通：

ping 192.168.1.18

2. driver 是否启动：

rosnode list | grep rm_driver

3. 真实关节反馈是否有：

rostopic echo -n1 /joint_states

4. rm_75_control 是否启动：

rosnode list | grep rm_75_control

5. MoveIt action 是否存在：

rostopic list | grep /rm_75/follow_joint_trajectory

6. rm_75_control 是否向 driver 发角度：

rostopic info /rm_driver/JointPos
rostopic echo /rm_driver/JointPos

7. MoveIt 是否加载了实物 controller：

rosparam get /move_group/controller_list

阶段产出：

写一份自己的排错 checklist：

- RViz 有模型但不动
- /joint_states 没有
- /rm_75/follow_joint_trajectory 没有
- /rm_driver/JointPos 没输出
- 关节角目标超限
- Execute result True 但实物没动

- 告诉 MoveIt 去找 /rm_75/follow_joint_trajectory

阶段 4：看懂厂家底层代码的“接口层”
================================

目标：

不用逐行吃透 socket 协议，但要知道每个底层节点的输入、输出、职责。

重点文件：

/home/ros/ws_rm_75_6f_robot/src/rm_75_robot/rm_75_control/src/rm_control.cpp
/home/ros/ws_rm_75_6f_robot/src/rm_75_robot/rm_75_driver/src/rm_driver.cpp

rm_control.cpp 要看懂：

- action server：
  /rm_75/follow_joint_trajectory

- 输入：
  control_msgs/FollowJointTrajectory

- 输出：
  /rm_driver/JointPos

- 中间处理：
  取 MoveIt 轨迹点
  三次样条插值
  定时发布关节角

rm_driver.cpp 要看懂：

- 读取 arm_ip
- socket 连接机械臂
- 订阅 /rm_driver/JointPos
- rad 转 degree
- 调用 Movej_CANFD
- 发送 JSON 到机械臂
- 接收机械臂反馈
- 发布 /joint_states

阶段产出：

写一张表：

节点名 | 输入 | 输出 | 作用

例如：

rm_75_control | /rm_75/follow_joint_trajectory | /rm_driver/JointPos | MoveIt 轨迹转角度透传
rm_driver | /rm_driver/JointPos | /joint_states | 机械臂 socket 驱动

阶段 6：TF / URDF / SRDF
=======================

目标：

理解 RViz 为什么能显示机械臂，MoveIt 为什么知道 arm 这个规划组。

重点概念：

URDF：

- 机器人模型
- link
- joint
- joint limit

SRDF：

- MoveIt 语义配置
- planning group
- disabled collision
- named pose

robot_description：

- 参数服务器里的 URDF

joint_states：

- 当前关节角反馈

robot_state_publisher：

- 用 joint_states + URDF 算 /tf

RViz：

- 显示 robot_description 和 /tf
- 本身不控制机械臂

练习命令：

rosparam get /robot_description
rostopic echo -n1 /joint_states
rostopic echo -n1 /tf
rosrun tf tf_echo base_link link7

重点文件：

/home/ros/ws_rm_75_6f_robot/src/rm_75_robot/rm_75_6f_description/urdf/rm_75_6f_description.urdf
/home/ros/ws_rm_75_6f_robot/src/rm_75_robot/rm_75_moveit_config/config/rm_75.srdf

阶段产出：

能解释：

- arm 规划组怎么来的
- joint limit 在哪里
- Fixed Frame 为什么要设 base_link
